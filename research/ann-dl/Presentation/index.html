MODEL 01 / SEGMENTATION

U-Net learns image → mask.

The dataset provides a SAR image and its manually created mask. We place the mask over the image to check that the marked slick follows the visible shape.

Actual paired SOS example: palsar_1839.

Why U-Net? A basic CNN can tell us whether an image contains a slick, but we also need to see exactly where it is. U-Net is designed to mark the slick pixel by pixel, producing a mask that shows its shape and location.
U-NET / DATA PREPARATION 01

Every patch has a unique identity.

The dataset has 8,070 image–mask pairs, all checked and readable at 256 × 256. The 21 full source scenes help us investigate where patches came from.

Folder + filename

train/palsar_0.png and val/palsar_0.png are different files. Including the folder prevents us from confusing their masks or source records.

U-NET / DATA PREPARATION 02

Three identical channels become one.

The SAR patches were saved as RGB, but every image contained the same values in its red, green and blue channels. We kept one channel because the other two repeated the same information.

256 × 256 × 3 → 256 × 256 × 1

We checked every output against the original channel: the pixel values were preserved exactly. The patches were already 256 × 256, so no resizing was needed.

U-NET / DATA PREPARATION 03

Turn masks into two labels.

Some supplied masks contained gray pixels. For this baseline, we use a threshold of 128 to choose between background and the labeled oil region.

Below 128 → 0

Background. For example, a pixel value of 80 becomes 0.

128 or above → 1

Labeled oil region. For example, 200 becomes 1.

Saved masks use black 0 and white 255; the loader converts them to 0 and 1. Originals are retained. Empty and full masks remain available for review.

U-NET / DATA PREPARATION 04

Prepare the inputs for learning.

We divide image values by 255 when loading, turning the original 0–255 range into 0–1. The loader returns NumPy arrays:

Image

[1, 256, 256]
float32 values from 0 to 1

Mask

[1, 256, 256]
float32 values of 0 or 1

The first 1 means one channel. The model receives the SAR image and learns against the mask; the overlay is only for visual inspection. All 8,070 prepared pairs passed loading and value checks.

U-NET / SOURCE RECOVERY

Where did each patch come from?

We search the original full scenes for image patterns that resemble each patch. This helps us understand whether training and validation share a source scene.

01 / SEARCH

Tile the scenes

Divide full-resolution scenes into overlapping 1,024 × 1,024 tiles.

02 / MATCH

Find patterns

SIFT finds distinctive features; FLANN searches for similar features; RANSAC checks whether they agree on position, scale and rotation.

03 / REVIEW

Compare crops

Align a proposed source crop with the patch and compare pixels before reviewing the candidate.

Log compression and percentile scaling help the source-image search; these are separate from the U-Net’s divide-by-255 normalization.

MODEL 02 / TRAJECTORIES

LSTM reads a history.

An LSTM looks at a vessel’s past positions in order and uses that movement history to estimate where it may go next.

Illustrative trajectory, not real AIS data or a model prediction.

Why LSTM? Unlike a model that looks at one position alone, an LSTM can use earlier positions to recognize how the vessel has been moving.

LSTM / DATA PREPARATION 01

Clean and organize the reports.

We scanned 8,529,554 NOAA records from 1 July 2020 and selected a northern Gulf of Mexico region for the first experiment.

Check and organize

Check coordinates and vessel-ID formats, convert times to UTC, group by vessel identifier (MMSI), and sort each vessel’s records by time.

Resolve duplicates

Remove 253 duplicate reports and exclude 66 conflicting reports with different positions for the same vessel and time.

Retained: 2,228,788 records across 3,359 vessel IDs, including positions, times, speed, course, heading, vessel type and navigation status.

LSTM / DATA PREPARATION 02

Divide reports into continuous segments.

A vessel’s whole day is not necessarily one continuous track. We start a new segment whenever the time between consecutive reports exceeds five minutes.

5,673 qualifying segments

Each lasts at least two hours and contains at least 120 reports. These are segments, not necessarily different vessels. Some are moving and others are mostly stationary, so duration alone does not select useful examples.

Five minutes is a provisional continuity rule, not a universal AIS reporting standard. The waterway check shown earlier applies to that example only.

LSTM / NEXT PREPARATION

From organized tracks to sequences.

Before training, we still need to handle missing-value codes and implausible jumps, choose sampling and short-gap rules, and create fixed-length input and output sequences.

We plan to hold out real positions to evaluate artificial 15-, 30- and 60-minute gaps, split by vessel, and fit feature scaling on training data only.

The 2020 AIS tracks are a separate trajectory benchmark; they have not been paired with the 2010/2017 SOS scenes.

FRAMEWORK / DEEP LEARNING

Python prepares. PyTorch will train.

Used so far

Python 3.12 runs our scripts. NumPy handles arrays and normalization; Pillow reads, converts and saves image–mask pairs.

OpenCV supports feature matching and alignment; Rasterio / GDAL read large SAR rasters and source windows.

Data and context

ASF Search / Requests find and download data. Shapely checks waterway geometry. Python’s CSV, datetime and ZIP tools handle AIS records, time and archives.

PyTorch is the proposed framework for U-Net and LSTM. U-Net and LSTM are architectures, not frameworks.
